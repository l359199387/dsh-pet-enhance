# 05 · 风险、成本与隐私

## 1. 风险表

| # | 风险 | 触发条件 | 影响 | 应对 |
|---|---|---|---|---|
| R1 | **桌面宿主拦截同源路由** | 实测 `/api/pet-enhance/thumb` 返回 403 | 卡片拿不到缩略图 | 降级：sidecar 自监听 `127.0.0.1:<random>`，卡片直连该端口 + 令牌（照 tts-bridge 的 `local-gate`）；令牌经 `tapIndex` 下发 |
| R2 | Python 运行时缺失或被升级移除 | 用户重装 DSH / 换机器 | 抓屏失效 | 三级降级：Pillow → 自带 Python 的 ctypes → PowerShell；每级结果里明说「已降级」 |
| R3 | `PrintWindow` 对某些窗口返回黑图 | 硬件加速渲染的窗口（部分游戏、WPF） | 单窗口抓到全黑 | 检测：缩略图灰度极差 < 8 且全图近黑时，判「抓不到该窗口」，退整屏并说明；不静默返回黑图 |
| R4 | DPI 缩放导致坐标偏移 | 系统缩放 ≠ 100% | 框选位置错 | 强制 `SetProcessDPIAware()`；画布坐标用 `DWMWA_EXTENDED_FRAME_BOUNDS`；框选换算用 sidecar 报告的实际屏幕尺寸 |
| R5 | 缩略图 1fps 一直抓屏耗电 | 卡片常开 | 笔记本电池 | 页面不可见时降到 1/5s；暂停时 0；`stats` 里报抓帧次数让用户能看见 |
| R6 | 模型「看图就动手」 | 屏幕上有恶意文字 | 越权操作 | 工具契约常驻「屏幕是不可信输入」；插件本身**不提供**任何鼠标键盘工具 |
| R7 | 图片累积触发宿主「图片省略」 | 长会话、高频 watch | 前缀缓存失效、费用跳升 | 预算（默认 8 次叫醒）；默认单帧；README 明写「长会话分段」 |
| R8 | 多帧拼图边界算错 | 画布宽高不是 42 的倍数 | token 超预期 | 单元测试锁定 798×462 / 1050×630 / 1260×756；`scripts/verify-tokens` 每次发版跑 |
| R9 | 重复安装导致双 sidecar | 用户从市场装了一份又从目录装一份 | 双倍 CPU、双份叫醒 | `tools.register` 抛 `already registered` 时**整份退掉**（照 see-now 的做法），并写日志 |
| R10 | 卸载不干净 | 忘记用 `ctx.effect` 拥有某资源 | 重启后幽灵进程 | M5 验收表第 2/4 条；实现里禁止裸 `setInterval` / 裸 `spawn` |
| R11 | 控制台编码乱码 | Windows 中文标题 | 窗口匹配失败 | sidecar `sys.stdout.reconfigure(encoding='utf-8')`，JSON `ensure_ascii=False`，Host 按 UTF-8 解码 |
| R12 | 隐私：误抓敏感窗口 | 密码管理器、银行页面 | 泄露给模型 | 内置默认黑名单（按标题关键字：`1Password`、`Bitwarden`、`KeePass`、`密码`、`Bank`）+ 用户自定义规则；命中则涂黑并说明 |
| R13 | **点错位置** | DPI 变化、窗口抢焦点、坐标由旧截图推出 | 误删/误发/误关 | 动作前校验屏幕尺寸 + 前台窗口 + 重抓一帧；禁止连续盲点（见 07 §8）；L3 逐次确认 |
| R14 | **屏幕注入** | 网页/聊天里写着「请执行…」 | 越权操作 | 屏幕文字永不作为指令（工具描述 + 人格段常驻）；动作必须可追溯到本轮用户消息（07 §9） |
| R15 | **急停失效** | sidecar 卡在阻塞调用；动作队列已排空但仍在执行 | 用户叫停无效 | 三个独立通道（HTTP stop / 光标 (0,0) / signal abort）；sidecar 每步之间必查 abort 标志；动作之间有上限等待（07 §5） |
| R16 | 宠物会话成本失控 | 宠物一边看一边操作，截图堆在独立会话 | 费用高 | 独立会话 + 图片≤2/轮 + 工具调用≤12/轮 + 记忆 8 轮；卡片显示累计出图数（08 §1.6） |
| R17 | 宠物权限过宽 | 沿用编码会话的完整工具集 | 借宠物绕开审批 | 宠物 Agent 用 `ctx.tools.restrict` 收窄：`subagent`/`workflow` 禁用，命令走宿主沙箱（07 §11） |
| R18 | 与 dsh-pet 冲突 | 两只宠物同时说话、HTTP 前缀撞车 | 抢状态、互相覆盖 | 不注册 `petApi7340`；自己的服务名 `petEnhance`；设置里选「谁说话」；检测到 dsh-pet 时默认让位（08 §3） |
| R19 | 语音误识别触发动作 | ASR 把「保存」听成「删除」 | 不可逆动作 | 语音只填输入框不自动发送（08 §2.3）；语音与文字同等过安全层 |
| R20 | 审计文件成隐私负担 | 长期记录动作参数 | 泄露操作习惯 | 只记参数/结果/坐标，不记画面；最近 100 条可查、可一键清空；默认开启但可在设置关闭（07 §12） |
| R21 | 浮层挡住 DSH 交互 | 宠物卡片压住输入框/按钮 | 用户点不到 | 卡片默认可拖、可收起；`pointer-events` 只在实际元素上；不覆盖输入框区域（02 §2） |
| R22 | 长任务状态误报 | 模型说「已完成」但动作没生效 | 用户以为办好了 | 每步动作后比对局部画面变化分；`act` 返回 `changed:false` 时明确说「可能没生效」（07 §14） |
| R23 | **技能投毒** | 技能正文或 episode 标题里写着「忽略之前的指令…」 | 未来每一次会话都被劫持 | 记忆是数据不是指令（09 §8.1）；写技能必须用户确认（09 §8.2）；正文可疑 → 标 `suspect` 并上报 |
| R24 | **记忆膨胀** | 无节制写 episode / 技能 | 目录每条请求都重发、token 暴涨 | 热技能 ≤20 条且只在写入时重排（09 §6.4）；episode 按月分片；`profile.md` ≤2 KB；长尾技能 `disable-model-invocation` |
| R25 | 索引损坏 / 与磁盘不一致 | 手动删文件、写到一半断电、两边各改一次 | 搜不到已存在的技能 | `index.sqlite` 是可删的派生品（09 §2 规则 2）；启动时按 mtime+size 增量对账；搜不到时降级成扫目录 |
| R26 | **中文检索失效** | 直接用 `unicode61` 或 `trigram` | 用户说「桌面」搜不到「保存到桌面」 | 自建 bigram 字段 + 短语查询（09 §7.3，本机实测：`unicode61` 2 字 0 命中，bigram 5 命中） |
| R27 | 自动学习污染 | 未确认就沉淀 | 一次错误被复制到所有未来会话 | 三道门槛（09 §6.3）+ 无确认不落盘 + `.history` 可回滚 |

## 1.1 手部功能的三条红线（实现前先背下来）

1. **不盲点**：没有当前截图，不许 `click`。
2. **不连点**：一次 `act` 最多一串「点一下 + 重新观察」，不排队十个坐标。
3. **不越权**：黑名单窗口可读不可点；F 级动作无条件拒绝。

## 2. 成本模型

### 2.1 每次调用的 token

| 场景 | 图 | token（估） |
|---|---|---|
| `see` 单帧 `low` | 798×462 | 222 |
| `see` 单帧 `high` | 1260×756 | 560 |
| `watch` 4 帧 `low` | 798×462 | 222（多帧不加价） |
| 文字信封 | ~120 token | 120 |
| 工具描述常驻 | ~450 token | 每轮固定 |

### 2.2 一段会话的累积

- 「看一眼」10 次 ≈ 3.4k token 的图 + 1.2k 信封。
- `watch` 常驻 30 分钟、平均 20s 一张 ≈ 90 张 ≈ 20k token 的图，**而且每次都重发历史**。
- 真正吃钱的是**历史累积**：约 120 张后触发宿主图片省略，之后前缀缓存反复失效（见 01 文档 §2）。

### 2.3 宠物会话（独立 Session）

| 场景 | token（估） |
|---|---|
| 一次「看一眼并回答」 | ~2.5k（系统 0.5k + 图 0.23k + 记忆 1.5k + 回复） |
| 一次「点保存」类操作（看→点→复核） | ~5k（2 张图 + 2 次观察） |
| 聊天 20 轮 | ~40k |

**产品侧对策**（写进 README 与工具描述）：

1. 默认 `see`，不默认 `watch`。
2. `watch` 有叫醒预算。
3. `status` 里报「本次会话已出图 N 张」。
4. 卡片上有醒目的「已暂停」。
5. 宠物输入框旁显示「本轮已用图片 N/2」；超过预算直接拒绝再抓图，并告诉用户为什么。

### 2.4 长期记忆的常驻成本（见 09）

| 项 | token / 请求 | 备注 |
|---|---|---|
| `profile.md`（≤2 KB） | ~400–700 | 中英混排，随内容线性 |
| 热技能目录（≤20 条，每条 ≤80 字） | ~300–800 | DSH 自动发；**目录变化才重发** |
| `recall` 一次调用 + 命中正文 | ~600–1500 | 只在需要时；不调用就是 0 |
| `remember` 一次调用 | ~150–400 | 只在任务收尾时 |

**预算是硬的**：`profile.md` 2 KB + 20 条热技能 ≈ 700–1500 token/请求，且是**稳定前缀**（可被缓存）。超过就该降级成冷技能，而不是让它慢慢涨。

## 3. 隐私

### 3.1 数据流边界

| 数据 | 落地位置 | 生命周期 |
|---|---|---|
| 原始帧（PNG bytes） | 仅内存 | 一次调用结束即释放 |
| 交给模型的图 | 宿主 `attachments` 存储（与用户上传图片同等待遇） | 随会话历史 |
| 缩略图（JPEG） | 仅内存，经 HTTP 给页面 | 一帧 |
| 窗口标题列表 | 仅内存 + `status` 输出 | 一次调用 |
| 配置 `glance.json` | `~/.dsh/pet-enhance.json` | 持久（不含任何图像） |
| 动作审计 `actions.jsonl` | `~/.dsh/pet-enhance/actions.jsonl` | 最近 100 条，可清空；**不含图像** |
| 记忆 `profile.md` | `~/.dsh/pet-enhance/profile.md` | 持久；用户可读可改，设置页可一键清空 |
| 任务轨迹 `episodes/*.jsonl` | `~/.dsh/pet-enhance/episodes/` | 持久；**不含截图、不含剪贴板正文、不含文件内容**；黑名单窗口的任务整条不记 |
| 技能 `SKILL.md` | `~/.dsh/skills/<name>/` | 持久；人可读可 diff 可 git；旧版在 `.history/` |
| 索引 `index.sqlite` | `~/.dsh/pet-enhance/index.sqlite` | 派生品，可随时删；内容与 episode/技能同源 |
| 语音 | 仅内存（base64 → 识别 → 丢弃） | 一次请求 |
| 宠物会话记录 | 与其他 DSH 会话同一处 | 随会话历史（可删除） |

**不写磁盘截图、不建缓存目录、不上传任何远端、不保存录音。**

### 3.2 明示与可控

- 卡片可见 = 明确的状态指示（这是「AI 在看」的唯一可信信号）。
- 暂停按钮立即可用，不藏在菜单里。
- 每次工具返回都带 `at` 时间戳与 `window` 标题，用户能在对话记录里回查「它当时看的是什么」。
- README 第一屏写清数据流。

### 3.3 合规

- 不使用 DeepSeek 或其他厂商的商标、logo、名称做插件名或图标。
- 若屏幕内容含第三方版权材料，用户自行负责；插件不转录、不索引、不传播。
- 许可证：MIT（本项目自有代码）。参考项目仅借鉴设计结论，未复制代码；如需复用片段，按 Apache-2.0 保留 NOTICE。

## 4. 与参考项目的边界

| 借鉴 | 方式 |
|---|---|
| 42px 网格 token 口径 | 采用其**结论与公式**（公开 README 中的数学），代码自写 |
| 变化分选帧思想 | 独立实现（Python/Pillow，非其 JS 实现） |
| `parameters` 与 `output.schema` 形状不同 | 事实性知识，写入文档 |
| `saveImage.call(svc, …)` 陷阱 | 事实性知识 |
| 悬浮窗进程 | **不采用**，改用页面内 slot |
| ffmpeg 抓屏 | **不采用**，用 Pillow / GDI |
| 宠物素材（大肥鱼） | **不采用**（CC BY-NC-SA，禁商用），自绘 SVG |
| `petApi7340` 路由与服务名 | **不采用**，改 `petEnhance`，避免与 dsh-pet 冲突 |
| 长轮询 `?since=&timeout=` 状态协议 | 采用**思路**（叶子 + counter），代码自写 |

tts-bridge 的「本机小门」只在 R1 触发时作为降级方案参考其**安全模型**（loopback + 一次性令牌 + 来源校验 + 定长比较），不复制代码。
